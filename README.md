# docrag-mcp

Local RAG over markdown documents, exposed as a [Model Context Protocol](https://modelcontextprotocol.io) server.

Point it at a folder of `.md` files, index them with a local embedding model
(Ollama, LM Studio, or any OpenAI-compatible `/embeddings` endpoint), and your
MCP client (Claude Desktop, Claude Code, Cursor, …) can semantically search
them from inside a chat.

Everything runs on your machine. No cloud, no API keys, no data leaves the
host.

## Features

- **MCP server over stdio** — plugs into any MCP-capable client.
- **Local embeddings** — bring your own OpenAI-compatible endpoint
  (Ollama, LM Studio, llama.cpp server, vLLM, …) or point it at OpenAI.
- **Vector search in SQLite** via [`sqlite-vec`](https://github.com/asg017/sqlite-vec) —
  a single `.db` file, no external vector database.
- **Heading-aware chunking** — markdown is split by `#`/`##`/… so results are
  returned at a useful granularity.
- **Incremental reindex** — re-indexing a file replaces its chunks atomically
  instead of duplicating them.
- **Tiny surface** — one config file, three CLI commands, four MCP tools.

## Requirements

- **Node.js** `>=20 <25`
- An **OpenAI-compatible embeddings endpoint**. The defaults target
  [Ollama](https://ollama.com) on `http://localhost:11434/v1` with the
  `nomic-embed-text` model (768-dim).

## Install

```bash
npm install -g docrag-mcp
```

Or run without installing:

```bash
npx -y docrag-mcp <command>
```

The binary is called `docrag-mcp`.

## Quickstart

### 1. Start a local embedding model

With Ollama:

```bash
ollama pull nomic-embed-text
ollama serve   # usually already running
```

### 2. Create a config and index your docs

From the directory you want to operate in (typically your project root):

```bash
docrag-mcp init       # creates docrag.config.json with sensible defaults
docrag-mcp reindex    # scans ./docs for *.md and builds ./docrag.db
```

### 3. Wire it into Claude Desktop

Add this to your `claude_desktop_config.json`
(macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`,
Windows: `%APPDATA%\Claude\claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "docrag": {
      "command": "npx",
      "args": ["-y", "docrag-mcp", "mcp"],
      "cwd": "/absolute/path/to/your/project"
    }
  }
}
```

Restart Claude Desktop. The `search`, `list_documents`, `index_markdown`
and `delete_document` tools will appear in the tool picker.

> The server loads `docrag.config.json` from its working directory (`cwd`),
> so set `cwd` to the directory where you ran `docrag-mcp init`.

### Claude Code

```bash
claude mcp add docrag -- npx -y docrag-mcp mcp
```

Run the command inside the project directory that contains
`docrag.config.json`, or edit the registration afterwards to pin the `cwd`.

## CLI

```
docrag-mcp <command>

Commands:
  init      Create docrag.config.json in the current directory
  reindex   Rebuild the vector index from markdown files
  mcp       Start the MCP server (stdio)
```

All three commands read `docrag.config.json` from the current working
directory (except `init`, which creates it).

## Configuration

`docrag.config.json` — generated by `docrag-mcp init`:

```json
{
  "dbPath": "./docrag.db",
  "docs": ["./docs"],
  "embeddingBaseUrl": "http://localhost:11434/v1",
  "embeddingModel": "nomic-embed-text",
  "embeddingDimensions": 768,
  "logging": false
}
```

| Field                  | Default                          | Description                                                                                   |
|------------------------|----------------------------------|-----------------------------------------------------------------------------------------------|
| `dbPath`               | `./docrag.db`                    | SQLite database file. Created on first use. Relative paths resolve against the config file.   |
| `docs`                 | `["./docs"]`                     | Directories scanned recursively for `*.md` by `reindex`.                                      |
| `embeddingBaseUrl`     | `http://localhost:11434/v1`      | OpenAI-compatible base URL. The server POSTs to `${baseUrl}/embeddings`.                      |
| `embeddingApiKey`      | *(unset)*                        | Optional. Sent as `Authorization: Bearer …` when present.                                     |
| `embeddingModel`       | `nomic-embed-text`               | Embedding model name passed to the endpoint.                                                  |
| `embeddingDimensions`  | `768`                            | Vector dimensionality. **Must match the model's output.** See [Changing models](#changing-models). |
| `logging`              | `false`                          | When `true`, writes a `doc-rag.log` next to the current working directory.                    |

### Example configurations

**LM Studio:**

```json
{
  "embeddingBaseUrl": "http://localhost:1234/v1",
  "embeddingModel": "text-embedding-nomic-embed-text-v1.5",
  "embeddingDimensions": 768
}
```

**OpenAI:**

```json
{
  "embeddingBaseUrl": "https://api.openai.com/v1",
  "embeddingApiKey": "sk-…",
  "embeddingModel": "text-embedding-3-small",
  "embeddingDimensions": 1536
}
```

### Changing models

The vector dimensionality is baked into the SQLite table at creation time.
If you switch to a model with a different output size, update
`embeddingDimensions` **and delete the existing `docrag.db`** before the next
`reindex`. The CLI will refuse to index with a clear error message if the
dimensions don't match.

## MCP tools

The `mcp` command exposes these tools to the connected client:

| Tool              | Input                              | Description                                                      |
|-------------------|------------------------------------|------------------------------------------------------------------|
| `search`          | `query: string`, `topK?: number`   | Cosine-similarity search. Returns the top `topK` chunks (default `5`). |
| `list_documents`  | *(none)*                           | Lists indexed files with chunk count and last-indexed timestamp. |
| `index_markdown`  | `filePath: string` (absolute)      | Indexes a single `.md` file; replaces existing chunks for that path. |
| `delete_document` | `filename: string` (relative path) | Removes all chunks for one document.                             |

## How it works

1. **Chunking** — `*.md` is split on markdown headings (`#` … `######`). Each
   chunk carries its heading, the raw body between that heading and the next,
   its ordinal index, and its source path.
2. **Embedding** — chunks are embedded in batches of 64 via the configured
   `/embeddings` endpoint.
3. **Storage** — chunk text goes into a `chunks_data` table; embeddings go
   into a `sqlite-vec` virtual table (`chunks_vec`) with cosine distance.
4. **Search** — the query is embedded, SQLite returns the nearest `k` vectors,
   results are reported as `score = 1 - cosine_distance` (higher is better).
5. **Replace semantics** — re-indexing a path deletes its old chunks inside a
   single transaction before inserting the new ones, so searches never see a
   half-updated document.

## FAQ / Troubleshooting

**`Could not find docrag.config.json in the current directory`**
`docrag-mcp` resolves everything relative to the current working directory.
Run `docrag-mcp init` first, or make sure the MCP client is launching the
server with the right `cwd`.

**`Embedding dimension mismatch during search/index`**
The embedding model's output size no longer matches the DB. Update
`embeddingDimensions` to match the model and delete `docrag.db`, or switch
back to a compatible model.

**`Embedding request failed: 404`** (or similar)
The configured `embeddingBaseUrl` isn't serving the OpenAI `/embeddings`
route, or the model name is unknown to that server. Check the URL
(it should end at `/v1`, not `/v1/embeddings`) and the model name.

**MCP output looks garbled / client won't connect**
Stdout is reserved for the MCP JSON-RPC frames; this server never writes to
it. If you're seeing text on stdout, something else in your launch command
is interfering. Set `logging: true` in the config to get a `doc-rag.log`
file for diagnostics.

**Nothing gets indexed**
`reindex` only picks up files ending in `.md`. Non-markdown files, symlinks,
and files without any heading (`#`) will not produce chunks — the chunker
only emits a chunk when it has both a heading and body text.
